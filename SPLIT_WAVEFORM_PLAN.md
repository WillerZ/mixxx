## Decision (developer, v3 — supersedes v1 and v2)

A full-height mirrored waveform squeezed into a half-height widget is **not**
half a waveform. Two new widgets are required:

- **top-half widget**: draws only the top half of its deck's waveform —
  zero line at the lane's bottom edge, positive lobes filling the lane;
- **bottom-half widget**: draws only the bottom half — zero line at the
  lane's top edge, negative lobes hanging down.

Stacked flush (deck 1 top, deck 3 bottom) they reassemble into one
contiguous waveform whenever the pair plays in lock; a slip shows up as
the two halves disagreeing about content at the playhead — and the
*other* half's content at the playhead is the real-time position of the
other deck, which is the snap-back reference.

Position semantics (explicit): **always track the deck's current play
state** (`VisualPlayPosition`, the audible position). The slip ghost and
slip-border decorations are not shown — the existing lower-half-shows-
slip-snap display is deliberately not preserved.

Zoom de-sync of the two halves (per-deck `waveform_zoom`) is **accepted** —
Mingo exposes no zoom UI.

## Mechanism: virtual double height + vertical crop

The entire vertical layout of a waveform is derived from the widget
renderer's height (`getBreadth()`): amplitude scaling, mirrored drawing
about the centre line, mark anchoring, beat-grid span, end-of-track line.
So a half is not a new renderer — it is the existing render at
**virtual height 2h**, cropped to one half:

- full waveform at virtual height 2h has its zero line at virtual `y = h`;
- **top half** = keep virtual `y ∈ [0, h]`: positive half-waveform, zero
  line exactly at the lane bottom edge;
- **bottom half** = keep virtual `y ∈ [h, 2h]`, translated up by `h`:
  negative half-waveform, zero line at the lane top edge.

Both halves at the same zoom therefore share identical pixel density —
stacked, they read as one waveform sliced horizontally.

### C++ scope

- New class `allshader::WaveformWidgetHalf final : public ::WGLWidget`
  (`src/waveform/widgets/allshader/`), constructed like
  `allshader::WaveformWidget` (which is `final` and cannot be subclassed —
  clone its ~250-line construction, trimming to the zoomed/opened feature
  set) with two differences:
  1. `resizeGL` passes `2h` down to `WaveformWidgetRenderer::resizeRenderer`
     (and the widget itself stays at height `h`);
  2. a per-pass vertical crop: clip band `[0, h]` (top variant) or `[h, 2h]`
     translated by `-h` (bottom variant).
- `WaveformWidgetVars`: add `m_waveHalf` (enum none/top/bottom), parsed
  from a new optional child of `<Waveform>`:

  ```xml
  <Waveform>
    <Channel><Variable name="chanBottom"/></Channel>
    <WaveHalf>bottom</WaveHalf>
  </Waveform>
  ```

- `WaveformWidgetFactory::createWaveformWidget`: when `m_waveHalf` is set
  and the backend is AllShader and the category is opened/zoomed,
  instantiate the half widget instead. Any other combination →
  `SKIN_WARNING`, render full-height (device-safe degrade).
  No new `WaveformWidgetType` enum, no preferences dialog change (the
  `DeveloperOnly` category gate requires `--developer` and is unusable on
  the device — the attribute approach bypasses all of that).
- Slip decorations: the half widget omits the slip ghost / slip-border
  renderer passes; position source stays `PositionSource::Play`
  (`VisualPlayPosition`) — i.e. the audible position, always.

### Details that need care (M2 checklist)

- **Clip mechanism** (open question, answer first): Qt scenegraph clips a
  widget's rendergraph passes at the widget rect — the *top* variant may
  get its crop for free (geometry beyond `h` falls outside the widget).
  The *bottom* variant needs the `−h` translation (precedent: the per-widget
  geometry transform in `matrixforwidgetgeometry.cpp`, used by vertical
  waveform orientation) — and if boundary clipping is *not* guaranteed per
  pass, both variants take an explicit clip band.
- **QPainter overlays** (`drawPlayPosmarker` triangles, passthrough label)
  are painted in real widget coordinates, not virtual ones: the bottom
  variant needs the marker triangles mirrored to the lane's bottom edge
  (or the play line left bare — decide on device at 210 ppi).
- **Odd heights**: virtual `2h` vs integer lane `h` — crop boundary is `h`,
  no subpixel split; verify at 1×/2× devicePixelRatio (device is 210 ppi).
- **Marks**: default-bottom-anchored loop-range bands land on the lane's
  bottom edge — correct for the bottom lane (virtual 2h), for the top lane
  Mingo sets those marks' `Align` to top (skin-side, no C++).
  Cue flags (`Align top`) are visible in both lanes as-is.
- Beat grid and EOT line are vertical spans — clipped by the band, correct.

### Implementation notes (M1–M3, resolves the checklist above)

- No new class: `WaveHalf` is a render mode of `allshader::WaveformWidget`
  (constructor argument, default `None`), not a clone of the `final` class.
- Clip mechanism, resolved: the only projection is
  `rendergraph::Engine::m_matrix` (ortho built in `Engine::resize`;
  `matrixForWidgetGeometry` is dead code in this tree). Half mode builds
  geometry for virtual height `2h` (`resizeRenderer(w, 2h, dpr)`) and
  `Engine::resize` gained a `projYOffset` so the ortho target is the band
  `[projYOffset, projYOffset + h]`: Top keeps offset 0 (crop at the
  viewport edge), Bottom maps virtual `[h, 2h]` onto the lane. One
  uniform, no translation hack, no scissor needed.
- Virtual-height logic lives in `resizeGL` — the only resize path with a
  GL context; the public `resizeRenderer` override is a deliberate no-op
  upstream, so all entry points funnel through it.
- Play marker is GL, not QPainter, in this backend: a texture of virtual
  height with the triangle baked at virtual `y = 0`. Result: arrowhead
  only in the top lane, one continuous play line through both — reads as
  a single marker across the split. Kept; confirm at 210 ppi.
- Mark label images are laid out within the virtual-height box, so
  `Align top` labels (Q, IN, OUT) show in the top lane, `Align bottom`
  (DefaultMark) in the bottom lane, and VCenter lands on the seam.
  Loop/intro/outro bands span both lanes and fade at the outer edges —
  one tinted column across the split. Accepted; tune on device.
- Odd lane heights are a non-issue: `2h` is always even and the crop
  boundary is exactly `h` in both ortho and viewport.
- Skin side shipped with current mark `Align` values; lane proportions
  (`WaveformSplitter` defaults) untouched until the device session
  (delete `[Skin],stackedWaveforms_splitSize` from the device cfg first).

## Bench (device)

1. Paired 1+3, in lock: the two halves read as one waveform; zero line is
   the seam; scrolling is pixel-identical speed between halves.
2. Follower slips: bottom half keeps scrolling its own audible content at
   the locked playhead; top half never disagrees with the pair; on
   snap-back, bottom content jumps to what the top half has been showing
   — the reference works.
3. Unpaired decks: each half is just a half-waveform display of its deck;
   nothing else regresses (overview, mini decks, library untouched).
4. Non-allshader fallback (dev software-render run): SKIN_WARNING once,
   full-height waveforms, no crash.
