## 1. Goal (review decision, verbatim intent)

One waveform display per deck pair: **top half lane = lower-numbered deck
(the pair leader, Channel 1/2), bottom half lane = higher-numbered deck
(the follower, Channel 3/4)**, on a **single shared time axis**. Replaces
the two per-deck `waveform_zoomed` widgets of a pair column, halving the
vertical footprint per pair.

Why it needs C++: each `<Waveform>` widget anchors its scroll window to
*its own* deck's visual play position. Two stacked widgets would each keep
their own deck centred, so a follower slip would look identical (always
centred) instead of showing the offset. A single widget with one
leader-anchored axis and two content lanes is the actual feature.

Non-goals: QML skin path, per-lane independent zoom/scroll, overview split
(the header overview stays leader-driven, `res/skins/Mingo/decks/overview.xml`).

## 2. Current architecture (verified on this tree, 2.6-beta line)

The 2.6 tree uses the **allshader** waveform stack, not the old
`WGLPaintHandler`:

- Skin `<Waveform>` node → `legacyskinparser.cpp:~1090`:
  `new WWaveformViewer(group, …)` then
  `WaveformWidgetFactory::setWaveformWidget(viewer, node, context)`
  (`src/waveform/waveformwidgetfactory.cpp`). The factory parses the node's
  children (group via `<Channel>`, `<Type>` category, colours, marks) into
  `WaveformWidgetVars` (`src/waveform/widgets/waveformwidgetvars.h`) and
  creates the concrete widget by configured type
  (`WaveformWidgetType::RGB = 12`, `Stacked = 16` in
  `src/waveform/widgets/waveformwidgettype.h`; category dispatch
  AllShader/Legacy at `waveformwidgetfactory.cpp:~1000`).
- The GL widget is `allshader::WaveformWidget final : public ::WGLWidget`
  (`src/waveform/widgets/allshader/waveformwidget.cpp`). `WGLWidget` lives in
  `src/widget/wglwidget.h` + `wglwidgetqopengl.cpp` and hosts a
  `rendergraph::Context` (`src/rendergraph/`).
- `WaveformWidgetRenderer` (`src/waveform/renderers/waveformwidgetrenderer.{h,cpp}`)
  owns the frame's scroll maths: `VisualPlayPosition::getVisualPlayPosition(m_group)`
  (`.cpp:110`), zoom factor, `m_firstDisplayedPosition[Play|Slip]`,
  `m_playMarkerPosition`, `transformSamplePositionInRendererWorld()`.
- Renderer stack: `addRenderer<T>(…)` template on `WaveformWidgetRenderer`;
  allshader renderer set in `src/waveform/renderers/allshader/`
  (`waveformrenderer.cpp`, `waveformrendererrgb.cpp` — note its existing
  "stacked" bool, `waveformrendermark(.range)`, `waveformrenderbeat`,
  `waveformrenderbackground`, `waveformrendererendoftrack`,
  `waveformrendererslipmode`, `waveformrenderstem`).
  All position-dependent passes consume the widget renderer's shared
  first/last-displayed window.
- Interaction: `WWaveformViewer` (`src/widget/wwaveformviewer.cpp:~29`) wires
  wheel/seek/scratch to the viewer's own group's controls
  (`waveform_zoom`, `scratch_position`, …).

Pair semantics this builds on (`DECK_PAIR_PLAN.md`): the leader is the single
transport authority; the follower replays the pair plane sample-locked;
**slip is strictly per-deck** — while the follower slips, its own playpos
diverges and on release it snaps back to the pair plane. Same track on both
decks is guaranteed by the pair load coordination, so both data planes share
one sample space and the leader-anchored window is directly meaningful for
the follower's waveform.

## 3. Design — one widget, two lanes, leader-anchored axis

### 3.1 Skin contract

New optional child on `<Waveform>`:

```xml
<Waveform>
  <Type>zoomed</Type>
  <Channel><Variable name="chanTop"/></Channel>      <!-- lane 1 (top) + timeline -->
  <SecondChannel><Variable name="chanBottom"/></Channel> <!-- lane 2 (bottom) -->
</Waveform>
```

`<SecondChannel>` is accepted only by the AllShader category; any other
backend logs one `SKIN_WARNING` and renders leader-only (graceful degrade,
including the software waveform fallback).

### 3.2 Plumbing (milestone M1)

- `WaveformWidgetVars`: add `QString m_secondGroup`.
- `WaveformWidgetFactory::setWaveformWidget`: parse `<SecondChannel>`
  (numeric → `[ChannelN]`), validate it is a player group and not equal to
  the main group; store on the widget like the main group flows today.
- `allshader::WaveformWidget::onInit`: when `m_secondGroup` is non-empty,
  build the renderer stack **twice** into two logical lane groups:
  leader stack draws with a vertical clip/scale to the top half, follower
  stack to the bottom half. Mechanism: per-renderer lane transform — a
  vertical scale of 0.5 + offset folded into the renderer model matrix
  (reuse `matrixforwidgetgeometry.cpp` helper) **and** a clip band on the
  rendergraph pass so lanes cannot bleed (Qt scenegraph clip node /
  `glScissor` on the OpenGL pass — pick per backend in the scenegraph
  abstraction; verify at implementation which clip primitive
  `rendergraph/scenegraph` exposes).
- The follower's `WaveformRenderer`-family instances are constructed with
  the follower group (so: own `EngineWaveform` texture, own
  `waveform_gain`, own hotcue/loop/cue marks, own beat grid, own stem
  selection, own end-of-track position) but **read the shared display
  window** from the widget renderer, which is leader-only:
  `m_group`, `VisualPlayPosition`, `waveform_zoom` stay the leader's. No
  renderer reads a position control directly — they all consume the widget
  renderer's computed window — which is why this composes without touching
  the maths.

### 3.3 Leader-anchored follower playhead (milestone M2, the useful bit)

While the follower slips, its waveform content stays fixed to the shared
axis (same track); what must move is the **follower's playhead line**. Add a
tiny dedicated pass (model: the end-of-track line renderer, one coloured
quad, vertical, clipped to the follower lane):

- x-position: `transformSamplePositionInRendererWorld(followerPlaySample)`
  with `followerPlaySample` from
  `VisualPlayPosition::getVisualPlayPosition(followerGroup)` — same
  vsync-smoothed source the engine uses, so no double-smoothing.
- Colour: skin `PlayPosColor` of the follower (or a fixed lane colour;
  decide on device). Hidden when `|followerPos - leaderPos| < ε`.
- Leader keeps the existing full-height play marker.

The follower's slip border (existing `waveformrendererslipmode`) is enabled
per-lane: follower slips → bottom lane outlines. Instant "who is slipping"
readout at a glance.

### 3.4 What stays shared (explicit decisions)

| Aspect | Lane behaviour |
| --- | --- |
| Scroll window / zoom / move | Leader only (widget group; interactions unchanged) |
| Play marker | Leader full height; follower offset line in-lane (§3.3) |
| Waveform content & per-deck gain | Own group per lane (independent data planes — the point) |
| Beat grid, hotcues, loops, cue/loop marks, EOT line | Own group per lane, clipped to lane |
| Slip border / slip ghost | Per lane, own group |
| Stems mute/solo | Already per-deck; each lane shows its own — the plan's acceptance use case (vocal vs instrumental) reads straight off the split |
| Pass-through (wheel) mode | Leader-only, whole-widget: at pass-through zoom the follower lane renders flat (its live line is meaningless while wheel-scrubbing the pair); return on toggle |
| `waveform_playmarker_position` | Leader's; follower's ignored (document) |

Mouse/touch on the widget keeps targeting the widget group (leader). On the
pair, follower-side writes are bridged to the leader by the pair command
bridge anyway, so any gesture anywhere on the display is pair-coherent.

### 3.5 Guardrails

- Same-track precondition: if follower has no track or a *different* track
  loaded than the pair coordination guarantees, fall back to follower lane
  drawn from its own first-displayed… **no** — simpler and safer: if
  sample rates or tracks differ (debug assert in debug builds; runtime:
  `track_samples` mismatch), hide the follower lane (flat background) and
  draw the leader full height. Never attempt cross-track sample-space
  mixing.
- All changes are gated on `m_secondGroup` non-empty: the single-deck path
  is byte-for-byte the current code, protecting the shared allshader path
  used by QML.

## 4. Alternatives considered and rejected

- **A — two half-height widgets + `<ScrollSource>` override** (follower
  widget borrows the leader's `VisualPlayPosition`/zoom). Smallest diff, no
  GL work. Rejected: the playhead marker is welded to the scroll anchor, so
  the slip offset — the one thing the view exists to show — is invisible;
  plus a visible seam/gutter and a second vsync'd widget.
- **B — one widget compositing two full `WaveformWidgetRenderer` instances
  via scissor bands.** Rejected: doubles the per-widget state machine
  (resize, events, track set, factory registration) for no gain over §3.2,
  which reuses one maths instance deliberately.

## 5. Performance & platform notes

- GPU cost ≈ today: two half-height lane passes replace two full widgets
  (Mingo shows 4 zoomed waveforms today → 2 split widgets; same uploaded
  sample data, ~half the fragment cost, one vsync draw instead of two).
- Device runs the allshader RGB path (210 ppi touchscreen, OpenGL ES via
  Qt); the added passes are one clip transform per renderer plus a
  single-quad line shader in the style of the existing EOT renderer — no
  new shader language features beyond what allshader already requires.
- 210 ppi: the lane seam must be drawn in GL (1 device px, dark colour) —
  a skin gap would show the pair-box background through it.

## 7. Manual bench (to be merged into `DECK_PAIR_BENCH_PROTOCOL.md` style)

1. Pair 1+3, same track, unpaired positions differ → on pair, lanes realign
   to one axis within one frame.
2. Follower slip (hotcue roll/scratch on follower): bottom lane content
   stays, follower playhead line leads/lags visibly against the leader
   marker; bottom-lane slip border on; release → line snaps back to centre.
3. Stem solo/mute per deck: top and bottom lanes visibly differ; nothing
   else moves.
4. Leader seek/loop/hotcue while follower slips: follower lane scrolls with
   the axis, its playhead keeps its offset; snap-back still lands.
5. Frame budget: device fps graph unchanged vs the two-widget pair today.
6. Follower unloads track / track mismatch: graceful leader-full-height
   degrade, no assert in release, debug assert fires in dev build.
