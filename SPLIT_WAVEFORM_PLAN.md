## Decision (developer, supersedes v1)

**No C++.** The per-pair split display is two ordinary half-height `<Waveform>`
widgets stacked with no gap:

- top half = lower-numbered deck of the pair (the pair leader, e.g. Channel 1),
- bottom half = higher-numbered deck (e.g. Channel 3).

Each widget keeps its single-channel dependency: its own group drives its own
scroll, playhead, beats, cues, gain. Nothing about a second channel is ever
referenced in C++.

Correctness argument (why this is enough for the pair):

- **Both locked:** the pair's follower replays the leader's transport
  sample-locked (`DECK_PAIR_PLAN.md`), so the two lanes scroll at the same
  pixels-per-second and read as one display.
- **One slipping:** slip is strictly per-deck; the slipping deck's own playpos
  keeps advancing, so its lane keeps scrolling its own content under its
  playhead, which stays locked at the marker — correct by construction, per
  lane. Snap-back appears as a content jump at the playhead — correct too.
- Same track on both decks (pair load coordination) ⇒ identical sample rate ⇒
  matching px/s at equal zoom.

## Trade-offs, accepted knowingly

1. **No slip-offset gauge.** Both playheads are centre-locked; how far a
   slipping deck will snap back is not readable, only the fact that it slipped
   (border/behaviour) and the snap-back jump. The v1 shared-axis single-widget
   design that *did* visualise the offset is archived at commit `124e9da946`
   if we ever want it.
2. **Zoom is per-deck.** Each widget zooms via its own deck's
   `waveform_zoom`. Mingo exposes no zoom UI, so both halves sit at the
   default forever. If zoom control is ever added (wheel in dev mode works
   per-widget and can descale the halves), either bridge `waveform_zoom`
   follower→leader in the pair control plane (small, engine-side) or give the
   follower widget a zoom-source override — decide then.

## Skin work (entire scope)

- `pair_column.xml`: inside the existing bordered pair box, stack two
  `wave_zoomed.xml` instances (top: `chanTop`, bottom: `chanBottom`) with no
  gutter between them; the deck-label gutter spans both lanes as today. The
  two `pair_row.xml` instantiations collapse into this one split row.
- `wave_zoomed.xml`: gains a `Size` min-height variable so the lane height is
  set by the column, not the template.
- Lane identity is free: each widget already draws its own deck-number mark
  (`DefaultMark`), so top lane shows "1", bottom shows "3".
- Heights: pair display shrinks from two rows to one split row; the freed
  height goes to the library via the `WaveformSplitter` default — new
  `SplitSizes` value to compute once lane heights are fixed (and remind:
  delete `[Skin],stackedWaveforms_splitSize` from the device cfg).
- Header overview stays leader-driven (as now) — it scans the pair plane.
- `pair_row.xml`: deleted if unreferenced after the rework.

## Bench (device)

1. Paired, playing: both lanes scroll at the same speed; "1" above "3"; reads
   as one display with a hairline seam (pair-box background colour).
2. Follower slip: bottom lane keeps scrolling under its locked playhead, top
   lane unaffected; snap-back lands as a content jump at the marker.
3. Stem solo/mute per deck: lanes visibly differ — the primary use case.
4. Unpaired decks: the halves behave as two normal waveforms did before
   (they are just two normal waveforms).
